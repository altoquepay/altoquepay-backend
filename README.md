# altoquepay-backend

REST API of **AlToquePay**, a web application for neighborhood corner stores (*bodegas*) to manage the credit they grant to their customers. It is built with FastAPI and consumed by the Angular web frontend, [altoquepay-frontend](https://github.com/altoquepay/altoquepay-frontend).

> **Status:** early development (`0.x`). The shared kernel, the ACL facade contracts, the `regulation` context (BCRP caps), the `iam` context (sign-in and passwords), the `stores` context (store registration, profile and administration), the `customers` context (customer accounts and their credit conditions), the `catalog` context (products and their images), the `credit` context (purchases, weekly French schedules and installments) and the `billing` context (cycles, statements, payments and late interest) are done. `reporting` is not implemented yet.

## Tech stack

- Python 3.12 or newer
- FastAPI, served by Uvicorn, with Pydantic for validation
- PostgreSQL 16 with SQLAlchemy 2.0 (async) and asyncpg
- Alembic for database migrations
- JWT authentication (PyJWT)
- OpenAPI documentation with Swagger UI, generated by FastAPI
- pytest, pytest-asyncio and HTTPX for tests
- Ruff for linting and formatting

## Getting started

### Requirements

- Python 3.12 or newer
- Docker with Docker Compose

### Run in development

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
```

On fish, activate it with `source .venv/bin/activate.fish`; on Windows, with `.venv\Scripts\activate`.

Install the dependencies:

```bash
pip install -r requirements.txt
```

Create your local configuration and set your own `JWT_SECRET` (generate one with `openssl rand -hex 32`):

```bash
cp .env.example .env
```

Start the database, apply the migrations and start the development server:

```bash
docker compose up -d
alembic upgrade head
fastapi dev app/main.py
```

The API starts on `http://localhost:8000` and reloads on file changes. The Swagger UI is available at `http://localhost:8000/docs`.

### Tests and linting

The integration tests need the database running. They create and migrate their own `<database>_test` database, so they never touch the data you use for manual checks.

```bash
pytest
ruff check .
ruff format .
```

## Configuration

Settings are read from environment variables, or from a `.env` file in the directory where the command runs. The `.env` file must not be committed.

| Variable | Description | Default |
| --- | --- | --- |
| `DATABASE_URL` | SQLAlchemy URL of the database, using the `postgresql+asyncpg` driver | |
| `JWT_SECRET` | Secret that signs the JWTs, at least 32 bytes | |
| `JWT_EXPIRE_MINUTES` | Lifetime of a JWT, in minutes | `60` |
| `CORS_ORIGINS` | Comma-separated origins allowed by CORS | `http://localhost:4200` |
| `APP_TIMEZONE` | Time zone of business dates | `America/Lima` |
| `FIRST_ADMIN_EMAIL` | Email of the system administrator created at startup if missing; empty creates none | |
| `FIRST_ADMIN_PASSWORD` | Initial password of that administrator, who must change it on first sign-in | |
| `RESET_TOKEN_MINUTES` | Lifetime of a password reset link, in minutes | `30` |
| `SMTP_HOST` | SMTP server for password reset emails; empty logs the links instead | |
| `SMTP_PORT` | Port of the SMTP server, used with STARTTLS | `587` |
| `SMTP_USER` | SMTP user, also the sender of the emails | |
| `SMTP_PASSWORD` | SMTP password | |
| `FRONTEND_URL` | Base URL of the frontend, used to build the password reset links | `http://localhost:4200` |
| `MEDIA_DIR` | Folder for uploaded files such as product images, served under `/media` | `media` |
